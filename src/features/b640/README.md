# Новый кабинет B640: как работать в разделе

Новый кабинет живёт рядом с прежним и открыт только аккаунту с флагом
`features.cabinetB640`. Раздел правит **только свой каталог**
`src/features/b640/<раздел>/`.

## Что править нельзя

`kit/`, `shell/`, `styles/`, `tokens.css`, `routes.ts`, `sections.ts`, `CabinetB640.tsx`,
прежний кабинет (`src/features/shell`, `career-shell.css`) и ожидания старых тестов.
Нужна правка основы — отдельный PR через оркестратора.

## Как добавить экран узла

1. Найдите узел в `routes.ts` по коду (`s01`, `o01c`): там адрес, заголовок, шаблон
   страницы, путь назад и вкладки. Макет узла — файл `slug` в каталоге макетов.
2. В `<раздел>/index.tsx` верните свой экран по `node.code`; для остальных узлов
   оставьте `NodeStub`:

   ```tsx
   export default function Section({ node, params }: SectionProps) {
     if (node.code === 's01') return <ProfileScreen />;
     return <NodeStub node={node} />;
   }
   ```

3. Экран рисует только страницу: `<div className="page" data-b640-node={node.code}>…`.
   Рейл, верхнюю полосу, путь, вкладки и нижнюю навигацию рисует оболочка.
4. Разметку и классы берите из макета один к одному: стили макета уже перенесены
   (`styles/base-*.css`) и действуют под `.b640`. Значок `<i data-i="bell">` из макета —
   это `<Icon name="bell" />`.
5. Данные берите из существующих клиентов API (`src/features/*/…Api.ts`), не меняя их.

## Что берёт экран у оболочки (`shell/`)

- `Link` — ссылка внутри кабинета; адрес узла: `buildNodePath('v04', { vacancyId })`.
- `useShell()` — `navigate`, `session`, `theme` и `setTheme`, `signOut`; параметры адреса
  приходят входу раздела пропсом `params`.
- `useScreenChrome({ title, crumb, bellCount, rootData })` — заголовок в полосе, подпись
  последнего звена пути (имя вакансии, компании), число у колокольчика, атрибуты корня
  из макета (`rootData: { mtight: '1' }` даёт `data-mtight="1"`).
- `CtxHead` — шапка контекста рабочего экрана («Отклик · Head of Engineering · Гринкод»).
- Вкладка «Подготовка» в «Откликах» ведёт на `/app/responses/next/interview`:
  `next` — ближайшее интервью, раздел сам находит отклик.

## Общие компоненты (`kit/`)

Смотрите вживую на витрине: `/app/kit` (аккаунт с флагом).

`Button`, `Icon`, `RowAction` (действие в строке), `SettingsGroup` / `SettingsRow` /
`Switch`, `PagedList` (по 20 и «Показать ещё»), `ResultLine` и `StatusLine` (результат,
ожидание и ошибка на месте действия), `useToast` (тост с «Отменить»), `Dialog` (окно, на
390 — лист), `InfoTip` (ⓘ: источник данных и методика), `Composer` (панель ввода),
`ActionDock` (главная кнопка, на 390 закреплена внизу), `useIsMobile`.

## Свой CSS раздела

Только если в макете нет нужного правила. Файл лежит в каталоге раздела, целиком внутри
`@layer b640.sections { … }`, каждый селектор начинается с `.b640 `, цвета и размеры —
токены `--career-*`. Атрибут `style` в разметке не работает (политика страницы) — размеры
задаются классами. Это проверяют `cssContract.test.ts` и `cssTokenContract.test.ts`.

## Правила интерфейса

Под элементами нет пояснительных строк (можно: ошибка поля, подтверждение необратимого
действия, одна строка пустого состояния, пример в плейсхолдере). Источники данных — в ⓘ.
Нет «пока недоступно», названий моделей и внутренней инфраструктуры. Ожидание, ошибка и
результат — на месте действия. Списки по 20 с «Показать ещё». На 390 главная кнопка
закреплена внизу. Тексты простым русским языком. Значки только Phosphor.

## Тесты и гейты

- Юнит-тесты рядом с кодом: `npx vitest run src/features/b640/<раздел>`.
- E2e раздела — в `e2e/b640/<раздел>.spec.ts`; вход с флагом:
  `mockSignedInCabinet(page, { cabinetB640: true })`. Сборка перед e2e: `npm run build`.
- Гейты макетов лежат в `e2e/b640/gates/`. Прогон на своём экране:

  ```ts
  import { expectGates } from './gates';
  await expectGates(page); // все семь; падение называет гейт, размер окна и элемент
  ```

  `npx playwright test e2e/b640` — все спеки нового кабинета на 1440 и 390.
- Снимки для сверки с макетом: `B640_SHOTS=1 npx playwright test e2e/b640 -g снимки`
  кладёт файлы в `.s13-shots/` (каталог не коммитится).

## Перенос стилей макета

`tokens.css` и `styles/base-*.css` сгенерированы из `b640.css` макетов:
`node scripts/b640/port-mockup-css.mjs <путь к b640.css>`. Руками их не правят: правка
вносится в макет и переносится скриптом (отдельным PR через оркестратора).
