# Reported SEO bot responses (B545)

`registerReportedSeoBotObservability` emits `seo_reported_bot_responses` through
Fastify's application logger every five minutes with data, and flushes a partial
window on orderly close. The timer is unreferenced and cleared on close.

The identity field is always `reported_user_agent_unverified`. A User-Agent is
spoofable: these reports do not prove that an official vendor crawler visited.
Multiple recognized bot names become `ambiguous`, never multiple verified visits.
Oversized User-Agents are ignored. The allowlist has exactly the 11 ticket names.

Only GET/HEAD public SEO path shapes are observed. Buckets contain allowlisted bot,
fixed surface and fixed status category (200 and 502 are distinct). No raw path,
query, User-Agent, referrer, address, cookie or candidate data is retained by this
observer. This does not alter or expand unrelated request logging policy.

Each interval has at most 256 buckets. Existing buckets continue counting after
the cap; new combinations increment `overflowResponses`, making `complete=false`.
Counts are window observations, not lifetime totals. Empty windows produce no
report. A process crash can lose the current window; there is no database state.

Coverage is only responses that reach Fastify. Responses generated by a reverse
proxy, CDN, or a failure before the application are outside this observation.
No matching report means no observation in that window, not proof of no crawlers.
Do not use synthetic User-Agent probes as evidence of an actual vendor visit.
