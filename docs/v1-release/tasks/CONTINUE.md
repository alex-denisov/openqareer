### B183 — очередь моделей (готово, на проде)

Очередь на проде, **одинаковая для персонального и обезличенного класса**
(решение владельца 2026-09-02 «одна очередь везде», записано в тикете):

```
nvidia/nemotron-3-ultra-550b-a55b:free → openrouter/free
  → gemini-3.6-flash (high) → gpt-5.6-luna (high)
```

Инфраструктура: шлюз Cloudflare **`openqareer`** заведён (аутентифицированный),
`CLOUDFLARE_API_TOKEN` работает и как `cf-aig-authorization`. Gemini ходит
только через шлюз. Ключ Gemini владелец решил не отзывать — INC-033 закрыт
решением.

**Пять дефектов, найденных только на живом проде** (ни один не ловился тестами):

1. Gemini отвергала контракт вывода (`400`) — виноваты `minLength`/`maxLength`/
   `maxItems`; снимаются в `geminiSchema.ts` только для транспорта Gemini.
2. Один несовместимый провайдер обрывал всю цепочку — теперь очередь идёт
   дальше и поднимает ошибку, только когда отказали все.
3. Очередь была списком **провайдеров**, а владелец назвал две модели одного
   провайдера — переделана на очередь моделей (`providerQueue.ts`), остывание
   по паре «провайдер + модель», модель в `routing.attempts`.
4. Глубина очереди стояла жёсткой тройкой — последняя ступень не пробовалась
   вовсе; теперь считается по самой очереди (`namedQueueDepth`).
5. **Общий корень трёх последних:** усилие рассуждения поднимали отдельно от
   потолка вывода. В обоих API это один бюджет — `geminiOutputBudget()` и
   `outputBudgetForRole(role, effort)` растят потолок вместе с усилием.

### B180 срез 1б — сделан, но упирается в продуктовое решение

Расчёт гипотез ролей переехал на сервер (`shared/poolRoleHypotheses.ts` +
`server/vacancies/roleHypotheses.ts`, маршрут
`GET /api/v1/candidate/role-hypotheses`). Причина переезда: браузер получал пул
**без требований** — их вырезает `matchedVacancyPage.ts` ради байтового бюджета
(INC-029). На проде маршрут отвечает `poolSize: 529`, 56 байт, 0.35 с.

**Панель по-прежнему честно отказывает,** потому что упирается в группировку.
Замер на живых 529 заголовках:

| Способ | Групп | ≥8 | Доля самого частого названия в группе |
|---|---|---|---|
| По названию целиком (сейчас) | 514 | **0** | — |
| По первому слову | 314 | 7 | мусор: «требуется» (43), «werkstudent» (8) |
| По корням ролей из словаря | 30 | 10 | **0.04–0.17** |

Даже лучшая группа («manager product», 18 вакансий) имеет всего 17% доминирования
самого частого названия; при пороге 0.30 не проходит ни одна. Значит принцип
среза 1 — «имя роли даёт самое частое реальное название» — **на этих данных не
реализуем**.
